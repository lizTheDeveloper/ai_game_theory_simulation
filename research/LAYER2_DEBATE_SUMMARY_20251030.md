## Round 3: Pattern Detection (Joint - 1.5h)

### Pattern Taxonomy (5 Types Identified)

#### Pattern 1: Threshold-Scaling Decoupling ⚠️ (60% of parameters)

**Definition:** Papers provide threshold values, simulations invent scaling functions

**Frequency:** 3/5 parameters

**Examples:**
- Climate: Papers say "35°C = limit, 28°C = deaths observed" → Simulation invents "10%/25%/50% per degree"
- Biosphere: Papers say "6 of 9 boundaries crossed" → Simulation invents collapse acceleration rate
- UBI: Papers say "experiment shows positive effects" → Simulation invents "5-10% improvement"

**Why it exists:**
- Academic papers focus on WHETHER effects exist (easier to publish)
- Quantifying MAGNITUDE requires larger datasets (harder, less common)
- Modelers need continuous functions (can't just have step functions)

**When acceptable:** Uncertainty documented (±50-100%), sensitivity analysis performed, alternative functional forms explored

**When problematic:** Presented as "research-backed", point estimate without uncertainty, no sensitivity analysis

**Consensus:** MOST COMMON pattern, DEFENSIBLE if uncertainty preserved

---

#### Pattern 2: Uncertainty Collapse 🚨 (40% of parameters)

**Definition:** Papers provide wide ranges (10× to 100×), simulations use point estimates

**Frequency:** 2/5 parameters

**Examples:**
- Biosphere: 100-1000 E/MSY (10× range in paper) → Single value in code
- Infrastructure: Qualitative regional variation → 3× point estimate (but within empirical 2-10× range)

**Why it exists:**
- Measurement difficulty (species count unknown, background rate uncertain)
- Monte Carlo computational limits (10,000 runs expensive)
- Presentation clarity (uncertainty bands complicate visualizations)

**Cynthia's view:** "Simulations need numbers, can't just say 'uncertain' - choose mid-range and document"
**Sylvia's view:** "10× uncertainty makes point-estimate modeling INVALID - must use parameter sweeps"

**Joint conclusion - Severity by range:**
- ±50% uncertainty: DOCUMENTABLE (point estimate + sensitivity)
- ±100% (2-3× range): REQUIRES uncertainty bands or parameter sweeps
- ±1000% (10× range): INVALIDATES point-estimate modeling entirely

**Consensus:** This is the MOST DANGEROUS pattern - biosphere 10× uncertainty is simulation-breaking

---

#### Pattern 3: Quantitative Fabrication ❌ (40% of parameters)

**Definition:** Specific numbers in code that don't exist in cited papers

**Frequency:** 2/5 parameters (1/5 after fixes)

**Examples:**
- Li et al. "0.86 L/GPU-hour" ❌ (paper only has L/kWh, not per-GPU) - FIXED
- Cooperative "4% vs 10%" ❌ (no Mondragon source found) - UNFIXED

**Why it exists:**
- Unit confusion (kWh ≠ GPU-hour, someone attempted conversion)
- Citation decay (someone reads "cooperatives have lower bankruptcy", invents plausible numbers)
- Optimistic assumptions (researcher believes cooperatives SHOULD have lower bankruptcy, assumes numbers)

**Consensus:** UNACCEPTABLE and HIGHEST PRIORITY to fix

**Fix protocol:**
1. Search for original source
2. If found, correct citation and verify numbers
3. If not found, REMOVE claim or replace with verified alternative
4. NEVER use "best guess" numbers with fake citations

---

#### Pattern 4: Context Mismatch Extrapolation ⚠️ (40% of parameters)

**Definition:** Research from narrow context extrapolated to broad context

**Frequency:** 2/5 parameters

**Examples:**
- UBI: Finland (2,000 unemployed, 2 years, welfare state) → Global (billions, permanent, includes failed states)
- Holodomor: Soviet Ukraine 1932-1933 (confiscation) → Nuclear winter 2040s-2070s (climate collapse)

**Why it exists:**
- Data scarcity (only 1 major UBI experiment in developed world)
- Optimistic generalization ("Finland shows UBI works" → "UBI works everywhere")
- Historical analogy limitations (Holodomor is only comparable famine with data)

**Cynthia:** "Data scarcity forces imperfect analogies, document limitations"
**Sylvia:** "Context mismatch invalidates extrapolation, should use 'unknown'"

**Joint compromise - Severity by mismatch type:**
- Geographic (Finland → Sweden): LOW
- Economic (developed → developing): MEDIUM
- Temporal (2 years → permanent): MEDIUM
- Mechanistic (confiscation → climate): HIGH
- Compound (all of above): CRITICAL

---

#### Pattern 5: Temporal/Unit Ambiguity ⚠️ (60% of parameters)

**Definition:** Time units or measurement units unclear or confused

**Frequency:** 3/5 parameters (1/5 fixed)

**Examples:**
- Holodomor "140-200 per 1,000": Annual or monthly? (10× difference!)
- Google water "2.1M L/day" vs "63M L/month": Documentation said daily but implied monthly (30× error) - FIXED
- Nuclear winter "75y" vs "30y": Xia models 75-year horizon, simulation compresses to 30 years (2.5× acceleration)

**Why it exists:**
- Historical data ambiguity (Wolowyna doesn't specify time unit explicitly)
- Unit conversion errors (multiply by 30 for monthly, but docs still say "daily")
- Timeline compression (designer wants acute crisis, compresses without documentation)

**Consensus:** DATA QUALITY issue, not methodological choice

**Fix protocol:**
1. Review original papers for explicit time unit statements
2. Cross-check with other literature (what's typical reporting?)
3. If ambiguous, use CONSERVATIVE interpretation
4. Document ambiguity explicitly in code comments

#### TIER 2: SILVER STANDARD ⚠️ (Empirically Bounded)

**Criteria:**
