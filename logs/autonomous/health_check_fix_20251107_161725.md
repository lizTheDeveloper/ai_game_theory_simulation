### Git Conflict Pattern
The status file conflicts occur when:
1. Researcher runs and updates status: "COMPLETE - 448s"
2. Next researcher run pulls main (which has a different status)
3. Git detects both modified the same line
4. Conflict markers prevent stash/checkout operations

### Prevention
Consider implementing one of:
1. **Append-only status log** instead of overwriting
2. **Timestamped status files** (e.g., `status_20251107_153001.txt`)
3. **JSON status with merge strategy** (always take newest timestamp)
4. **Status in commit message only** (no tracked file)
